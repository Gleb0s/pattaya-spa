# Публикация многостраничной «Паттайи»

## До загрузки

1. Сделайте резервную копию текущего сайта и конфигурации хостинга.
2. Подтвердите цены, составы программ, контакты, права на материалы и выбранный домен.
3. Сборка рассчитана на **https://pattaya-massage.ru/**, без www, в корне домена.
   Для другого домена измените `origin` в `content/site.json` исходной сборки,
   выполните `python3 scripts/build.py` и заново подготовьте архив.
4. Если сохраняются неизвестные старые страницы с трафиком, предварительно
   выгрузите их из панели вебмастера и дополните карту перенаправлений.
   В сборке учтены 11 известных URL услуг, не все возможные страницы старого сайта.

## Что загружать

Распакуйте `Pattaya-SPA-multipage-deploy.zip`. В корне публикации должны лежать:

```text
index.html
404.html
styles.css
pages.css
app.js
data.js
robots.txt
sitemap.xml
assets/
massazh/
spa-programmy/
spa-dlya-dvoih/
ceny/
spa-devichnik/
podarochnye-sertifikaty/
abonementy/
o-salone/
kontakty/
karta-sayta/
```

Сохраняйте структуру папок. Каждая страница — настоящий `index.html` в своём
каталоге. Сборка уже выполнена; серверный JavaScript, база и PHP не требуются.
`DEPLOY.md` и `SEO.md` публиковать не обязательно.
Папки исходников `content/`, `scripts/` и Node-сервер не включены в deploy-архив.

## Настройки хостинга

### Apache

В архив включён `.htaccess`: DirectoryIndex, 404, нормализация `/index.html`
и 11 перенаправлений Tilda. Для него нужны разрешённые настройки AllowOverride
и mod_rewrite. Не затирайте существующие правила домена, HTTPS, доступа или кеша:
объедините конфигурации. Если хостинг не разрешает директивы Options, перенесите
соответствующие настройки в панель или согласуйте конфигурацию с поддержкой.

### Nginx

В `deploy/nginx-snippet.conf` находится **фрагмент для существующего server-блока**.
Это не полная замена конфига сервера и не инструкция менять TLS-сертификаты.
Укажите корректный корень сайта в действующей конфигурации, примените правила
и проверьте конфиг штатным инструментом хостинга перед перезагрузкой.

### Другой статический хостинг

Включите выдачу `index.html` внутри папок. В панели отдельно задайте:
- страницу `/404.html` с HTTP-статусом **404**, не 200;
- постоянные редиректы старых URL из `deploy/redirects.json`;
- единственную основную версию HTTPS-домена;
- нормализацию адресов с `/index.html` и без завершающего слеша.

**Не используйте SPA fallback**, который возвращает главную с кодом 200
для любого неизвестного адреса. У этого сайта разные HTML-документы.

## Проверка после загрузки

- Главная и `/massazh/` отвечают 200; карточка открывает отдельную страницу.
- Один старый `/tproduct/...` перенаправляет 301 на соответствующую услугу.
- Неизвестная страница возвращает 404.
- Canonical, sitemap, OG и JSON-LD указывают на правильный боевой домен.
- `/robots.txt` и `/sitemap.xml` открываются; каталог содержит 22 URL, не 404.
- Переходы на телефоне, ссылка на карту и телефон работают.
- Калькуляторы сертификатов, девичника и абонементов считают нужные значения.
- На хостинге/в CDN сброшен старый кеш HTML.

После подтверждения домена в Яндекс Вебмастере и Google Search Console
добавьте sitemap и проверьте несколько ключевых URL. Учётные записи не подключены
и отправка сайта в эти сервисы в рамках работы не выполнялась.

Смена структуры не заменяет дальнейшую работу с содержанием, спросом,
карточкой организации, отзывами и анализом результатов.

## Быстрый просмотр без сервера

Откройте корневой `index.html` двойным кликом. JavaScript распознаёт `file://`
и адаптирует только локальные ссылки, в том числе карточки после переключения
категорий. Открывайте HTML-файл, а не адрес папки: папку браузер показывает
как список файлов. После публикации это поведение отключается автоматически —
чистые URL, canonical и sitemap не меняются. Для локального просмотра без
JavaScript и проверки редиректов используйте сервер из исходной сборки.
